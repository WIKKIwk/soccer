# IDN-001 — Administrator ID and minimal actor identity

**Status:** Accepted  
**Decision date:** 2026-08-08  
**Depends on:** [ARC-003 UUID strategy](ARC-003-uuid-strategy.md), [P0-001 product contract](P0-001-product-contract.md)

## Decision

The identity boundary defines:

- `AdminUserId` — a typed newtype around the canonical UUID value;
- `ActorIdentity::Administrator(AdminUserId)` — the minimum actor identity
  needed by the first administrator-controlled vertical slice.

`AdminUserId` accepts a UUID generated by the application or infrastructure
boundary. The domain does not call an operating-system UUID API and does not
generate IDs itself. Display and transport layers can use the canonical
lowercase, hyphenated UUID representation through the typed accessor.

## Scope boundary

This increment does not define credentials, password hashing, sessions,
administrator status, roles, permissions, competition access, or persistence.
Those concerns remain separate identity increments. The actual administrator
employee record is still unresolved until the controlled development actor is
created by IDN-002.

`ActorIdentity` is an ownership identity, not an authorization decision. A
caller must still pass through the application authorization boundary before a
command can mutate state.

## Verification

Database-free domain tests verify UUID round-trip/display behavior and that the
actor wrapper preserves the administrator ID explicitly. No UUID is generated
inside the domain module and no database record is created by this increment.
